# Звіт до Практичної роботи №4 (Доставка їжі / Glovo)

## 1. Обґрунтування дій ON DELETE (Завдання 2)
- **Зв'язок з таблицею `restaurants` — дія `ON DELETE RESTRICT`**: 
  Заборонено видаляти ресторан із бази даних, якщо існують оформлені замовлення, які на нього посилаються. Це запобігає втраті історії продажів та появі «зламаних» записів у фактовій таблиці.
- **Зв'язок з таблицею `clients` — дія `ON DELETE SET NULL`**: 
  Якщо клієнт видаляє свій акаунт, історія старих замовлень залишається для звітності ресторану, але поле `client_id` стає порожнім (`NULL`), оскільки прив'язка до конкретного профілю більше не потрібна.
